Shared project memory for coding assistants (Codex, Claude Code, Gemini CLI, …). `CLAUDE.md` and `GEMINI.md` load this file. Keep it up to date when something important changes.

## What this is
VibeVideo AI is VibePlayer (a free Windows media player with a YouTube-style interface, C#/WPF on LibVLC 3.0.24 through LibVLCSharp 3.10.1) plus an AI scene filter that runs on the user's PC. It finds nudity/sex and kissing scenes, marks them in pink on the progress bar and skips them. The user controls every scene in "Scenes to skip". Version 0.1.0 is a free preview for x64 and ARM64.

- Website: https://www.nomanshafiq.com/vibevideo-ai/ (download page) and https://www.nomanshafiq.com/blog/vibevideo-ai/ (field note). The site lives in a separate repo: `D:\Work\nomanshafiq-portfolio` (`src/data/vibevideo-ai.ts`, `public/updates/vibevideo-ai.json`, `docs/VIBEVIDEO-AI-CONTENT.md`).
- The launch video project is `D:\Work\vibevideo-ai-launch-video` (Remotion; the player shots recreate this app's interface).
- Built from VibePlayer (https://github.com/MuhammadNoman76/VibePlayer, local `D:\mediaplayer`). VibePlayer's own features all remain: skip mode for parts you mark (amber), hold the right side for 2x, wheel tricks, resume, multi-window choice, automatic updates.

## Layout
- `src/VibePlayer/` holds the app (the project and namespaces keep VibePlayer's names).
  - `Core/Ai/`: cross-target scan data (`SceneScan`, with the user's choices: "don't skip" ranges and moved edges), `SceneFinder` (scores → scenes, then the user's choices applied), LibVLC `FrameGrabber`, `SceneScanner`, `AiEngine`, `AiHeadless` (test without a window).
  - `Core/Ai/Onnx/`: x64/ARM64 only (`VIBE_AI`): Windows ML device selection (`AiHardware`), models (`ModelStore`), `OnnxSceneAnalyzer`.
  - `Views/PlayerView.Ai.cs`: the AI menu, scanning and the pink marks. `Views/PlayerView.Scenes.cs` + `Views/ScenesDialog.xaml(.cs)`: "Scenes to skip" (keep/skip, move start and end, watch once, back to the AI's times, remove, add). `Views/ScenesCapture.cs`: `--capture-scenes` renders that window off-screen to a PNG.
  - `Assets/ai-prompts.json`: prompt embeddings, made by `tools/ai/embed_prompts.py`.
- `installer/VibeVideoAI.iss`: the Inno Setup script (`/DEdition=x64|arm64`, `/DAppVersion=`). `associations.iss` is generated by `build-ai.ps1`; don't edit it by hand.
- `release/`: the published installers and `VibeVideoAI-SHA256SUMS.txt`. The website's download links and the update feed point here.
- `publish/` and `dist/` are build output (git-ignored).

## Models and hardware
- Downloaded on first use and SHA-256 checked: CLIP ViT-B/32 image encoder (fp16 for NPU/GPU, fp32 for CPU; the 8-bit version gives wrong scores, don't use it). NudeNet 320n is optional, off by default and downloaded only when switched on (AGPL-3.0: settle the licence question before turning it on by default).
- Windows ML (`Microsoft.Windows.AI.MachineLearning`) downloads the PC's certified execution providers (Intel OpenVINO on the owner's laptop → the AI Boost NPU). Order: NPU, best GPU (DirectML), CPU. The stock DirectML NuGet can't reach NPUs.
- Measured on the owner's laptop (Intel Core Ultra 5 135U, installed 0.1.0, test reel): NPU about 36x real time (13 ms per picture), Intel graphics 21x (23 ms), CPU 11x (44 ms); a 1080p clip 17-18x on the NPU (decode-bound).
- Pitfalls found the hard way:
  - Don't use `Media.Parse` in the grabber: parse + dispose crashed the process (ntdll access violation) a few seconds later.
  - smem timestamps are on VLC's system clock; only differences within one run are valid. VLC's `fps` filter outputs each picture one interval late and repeats the first (corrected in `FrameGrabber.OnPostrender`).
  - The ONNX Runtime CPU provider can't load the fp16 CLIP file; DirectML/OpenVINO can.
  - The user's choices are matched to the AI's own scene range (`TimeRange.SameScene`, overlap of at least half), never to the moved range.

## Testing without a window
- `VibeVideoAI.exe --ai-scan <video> --ai-out report.json [--ai-processor auto|npu|gpu|cpu] [--ai-no-nudenet] [--ai-focus <s>] [--ai-timecode] [--ai-load-only]` (NudeNet is on in this test unless `--ai-no-nudenet`; the app's default is off). `VIBEVIDEOAI_MODELS=<folder>` uses local model files.
- `VibeVideoAI.exe --capture-scenes out.png [--select ai|kept|you] [--no-edit]` renders the Scenes to skip window with example scenes.
- Logs: `%APPDATA%\VibeVideoAI\info.log` and `error.log`.

## Compatibility rules (don't break)
- The project still compiles for net10.0-windows and net48 (the AI is unavailable in net48 and x86 builds, which still play video). Only x64 and ARM64 are released. Use `Compat`, `MathEx.Clamp` and the polyfills; no `Math.Clamp`, `Environment.ProcessPath` or `File.Move(…, true)` directly.
- 32-bit: never import `GetWindowLongPtrW`/`SetWindowLongPtrW` directly; use the `IntPtr.Size` wrappers in `Interop/Native.cs`.
- The libvlc folder follows the process CPU (`win-x64` or `win-arm64`).

## Build and release
1. Bump `<Version>` in `src/VibePlayer/VibePlayer.csproj` (or pass `-Version`).
2. Build: `powershell -ExecutionPolicy Bypass -File build-ai.ps1 [-Version X.Y.Z]`. It publishes x64 and ARM64 to `publish\vibevideo-ai-<edition>` and writes `dist\VibeVideoAI-Setup-<ver>-<edition>.exe` and `dist\VibeVideoAI-SHA256SUMS.txt`. The .NET SDK is at `%LOCALAPPDATA%\Microsoft\dotnet\dotnet.exe`; Inno Setup 6 at `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`. Each installer must stay under 100 MB (GitHub's file limit).
3. Copy the installers and the checksum file into `release/`, commit and push this repo first, so the download links exist.
4. In the website repo, update `src/data/vibevideo-ai.ts` (version, dates, exact bytes and SHA-256) and `public/updates/vibevideo-ai.json`, run `npm run verify`, then commit and push.
5. Uninstalling deletes `%LOCALAPPDATA%\VibeVideoAI` (models, scans, cache); settings in `%APPDATA%\VibeVideoAI` stay.

## Testing on the owner's PC (be careful)
- The owner uses VibePlayer daily. Check that no VibePlayer or VibeVideo AI process is running before launching test builds, and never pop windows over a full-screen app (prefer the headless switches above).
- Back up `%APPDATA%\VibeVideoAI`, `%LOCALAPPDATA%\VibeVideoAI`, `%APPDATA%\VibePlayer` and `%APPDATA%\vlc` before tests and restore them exactly afterwards.
- Test installers per-user in a scratch folder (`/CURRENTUSER /DIR=… /TASKS=""`), then uninstall. Don't touch installs in Program Files or the owner's file associations.
